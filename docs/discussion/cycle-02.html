Lessons we learnt

five mechanically different searches landed within 0.35 log2 of each other on both targets, ~4.3/~9.7 below the TreeSA references confirmed

root cause
the gain comes from the shared objective change — sc_target = cap instead of omeco's default 20 — plus full-budget anytime annealing; the default target drags search toward low-memory/high-flop trees on instances whose optimum sits at sc 33-53
evidence
018's ablation (soft penalty at cap: reg3 56.8 -> 40.0, its DP gained 0.002); the 0.35-wide five-way cluster; references measured at default sc_target
implication
publishable object is the sc-budget-aware annealing principle, not a move set; fix omeco TreeSA's default sc_target footgun in the library

014 and 016 scored 4-5 log2 worse than their own smoke tests; the SA family replicated to within 0.1 suspected

root cause
heavy-tailed run-to-run variance in LNS/tabu; a single scored run samples the tail, while SA-family methods are intrinsically low-variance
evidence
016's LOG documents a 1-in-5 tail incl. 45.1; 014 smoke 40.3 vs scored 45.0
implication
variance is a first-class quality axis; high-variance mechanisms need internal restart-and-min to compete per single run

simplification preprocessing (013) gained nothing despite 106 rank-1 tensors on sycamore confirmed

root cause
TreeSA spends negligible budget on trivially-decidable contractions; search-space size was not the binding constraint
evidence
013 held the optimizer at baseline and scored at reference level on both targets
implication
blacklist search-space reduction as a standalone quality lever on these targets

Literature check

sc_target = cap as the operative annealing objective matches the memory-bounded practice in [kalachev_2021_multi] (β-penalty on log2(M/Mmax) overflow) — our finding sharpens it: on instances whose optimum sits near the cap, target-the-cap dominates target-a-low-sc. The five-way basin convergence at matched budget echoes the plateau behavior described in [gray_2020_hyper]'s anytime curves. No paper in .knowledge/ reports the specific failure mode "default sc_target sabotages TreeSA on high-sc-optimum instances" — novel at the library/engineering level; the record-sized quality gains need a cotengra head-to-head before any external claim.
