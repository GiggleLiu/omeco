Lessons we learnt

004 passed the speed bar with baseline algorithm + scheduling hygiene; every novel draft scored below it confirmed

root cause
baseline TreeSA defaults overshoot: converged tc is reached in <= T/4 on all dev families, so measured budgets contain ~4x slack that only schedule hygiene can harvest
evidence
004 per-instance table (T/4 tc == full-budget baseline on 8/9 graphs); 006 LOG (budget-bug fixes moved score more than its DP); holdout replication on unseen sizes
implication
honest claim: TreeSA-class quality at 4x less optimizer time; the +1.0 quality bar remains the open research target

five SA-family attempts failed only on reg3_250 at reduced budgets, almost always via the sc-cap guard (sc 34-36 vs cap 35) confirmed

root cause
TreeSA's soft sc_target=20/weight-1 objective exerts no pressure near sc 33-36, so short anneals emit whatever sc the trajectory has; attempts inherited this objective
evidence
identical failure signature across 001/002/003/008/010; 008 LOG: sc-floor tracking halved but did not eliminate violations
implication
treat sc as a hard constraint (reject/penalize above baseline_sc+2) in any future search objective

all constructive drafts (005 min-cut, 007 elimination-order, 009 beam) matched TreeSA on structured graphs but lost 4-17 tc on reg3, worsening with size confirmed

root cause
reg3 graphs are expanders: no balanced separators, no low-width monotone construction; only iterative refinement over full trees finds their low-width structure
evidence
005 reg3_250 tc 59 vs 47; 007 plateau 64 vs 47 at 8s; 009 66-73 vs 47 with sc blow-ups
implication
blacklist pure constructive methods on expander-dominated suites; use at most as seeds
