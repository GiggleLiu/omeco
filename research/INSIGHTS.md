### Local search on contraction trees
- **Technique**: Simulated annealing over full binary contraction trees using four O(1) local rewrites applied at any internal node: `(a*b)*c → (c*b)*a`, `(a*b)*c → (a*c)*b`, `a*(b*c) → b*(a*c)`, `a*(b*c) → c*(b*a)` (associativity+commutativity swaps of a subtree with its uncle). Score with gain Δf = f(x) − f(l(x)) on the hardware-aware objective f(T) = β·max(log2(M/Mmax), 0) + log2(C + α·RW), where C = flops, RW = read/write volume, α = arithmetic intensity (≈16 on a V100), β = memory-overflow penalty — each move needs only a local cost update, so millions of steps are cheap. Interleave slicing into the same search: keep a sliced-leg list S, and every K steps (K ≈ 1e5) with probability 1/2 either add the leg giving the best memory reduction or remove a random leg from S (these steps need a global re-score, hence the large K). Kalachev et al.'s method is the direct ancestor of TreeSA; to beat it, upgrade the SA machinery: acceptance P = exp(−log(c_new/c_cur)/T) on log-cost so temperature scales are instance-independent, exponential wall-clock-indexed cooling T(t) = T0·(Tf/T0)^t for t = elapsed/budget, p-way parallel "division": run ⌈N/p⌉ steps independently on p workers per temperature and keep the best, plus restart-from-best after a fixed number of non-improving temperature iterations. A second, coarser move class from the partitioning paper: detach a randomly chosen subtree and reattach it elsewhere ("subtree shift"), choosing the destination greedily by objective |T_src| + |T_dst| − |T_result| (directed selection beat random selection and gave ~8x cost reduction over the naive baseline).
- **Applies when**: A feasible tree already exists (greedy seed); any graph size where per-move cost updates stay local; anytime/time-budgeted regimes — the log-cost acceptance and wall-clock cooling make it robust without per-instance temperature tuning; memory-constrained targets, since slicing co-optimizes inside the same loop.
- **Limits**: Local rewrites alone get stuck in basins on structured/large networks (hence restarts and multi-trial runs); slicing moves force expensive global re-evaluation; results are stochastic (~5% spread on random graphs); coarse subtree-shift moves can wildly change cost, requiring the probabilistic acceptance to be well-tempered; both papers still tune T0/Tf per problem family.
- **Sources**: [kalachev_2021_multi], [anon_2025_optimizing]

### Partition/cut-based tree construction
- **Technique**: Build the tree top-down by recursive balanced bisection; each cut is one contraction, so cut weight (sum of log2 index dimensions) = log2 cost of that contraction. FlowCutter's engine: solve incremental s-t max-flow on the unit-capacity graph, extract the least-balanced min cut, then repeatedly "pierce" one cut-boundary node into the source side (prefer piercings that don't grow the cut, else a distance heuristic) — producing a whole Pareto set of (cut size, balance) cuts per run, from which you pick e.g. minimum expansion = cut/(smaller side) subject to a balance bound. Drive nested dissection with a max-priority queue on bag/subproblem size and abort a branch early once its bound can't improve the current width. Staudt et al.'s three fixes to the cotengra-style KaHyPar recursion, each removing a bias: (1) decouple tree balance from partition balance — instead of making both halves children, contract one half (child) and inject its result as a single node into the other half (parent network), so a balanced cut (imbalance ε = 0.05) can still yield arbitrarily skewed trees; (2) add a "free node" F connected by all free/output indices before cutting, so the cut objective counts free indices that actually appear in contraction cost (~20% flop reduction alone on max-cut circuits); (3) cost-based node weights from a provisional greedy tree: cost-weight(T) = max over ancestors A of log2(cost(A))·shared-indices(T, A), averaged over ~10 partitioner repetitions. Glue: priority queue over subnetworks by greedy-estimated cost, reject a cut if parent+child greedy cost exceeds the pre-cut greedy cost, optimal DP below 15 nodes, 256 randomized greedy trials per subnetwork.
- **Applies when**: Large structured/sparse networks (hundreds to thousands of tensors — Sycamore m=20, 5908-tensor max-cut circuits) with global separator structure that bottom-up greedy misses; networks with output/free indices; anytime budgets of seconds to minutes; hypergraphs (COPY tensors as hyperedges) are handled natively by KaHyPar-style partitioners.
- **Limits**: Min-cut is still greedy per level — cheap cuts now can force expensive contractions later (only partially fixed by balance/cost weights); cost-node-weights depend on a provisional greedy tree, so bad seeds mislead the partitioner; without the free-node fix the other improvements were ineffective on free-index networks; exact-width methods (Tamaki-style DP) beat FlowCutter on small instances but fail entirely on large ones; heavy hyperparameter surface unless the Staudt defaults are adopted.
- **Sources**: [strasser_2017_computing], [staudt_2024_improved], [gray_2020_hyper]

### Greedy heuristics & cost functions
- **Technique**: Replace the single opt_einsum greedy score with a portfolio of cost functions, evaluated per instance at runtime and the winner used for path generation. Baseline score: cost(i,j) = size12 − (size1 + size2); the two key named variants are size12 − min(size1, size2) (produces balanced trees) and size12 − max(size1, size2) (produces skewed trees — better for chain-like/matrix-vector-dominated networks); Orgler & Blacher tuned further variants on planar/regular/grid/random-graph instances and select by whichever minimizes flops (or max intermediate size) on the instance. Because each greedy run is near-linear (O(n·k), k = max tensors sharing an index), the portfolio computes hundreds of paths in the time competitors compute a few — at a 1-second wall-clock cap it beat opt_einsum greedy/random-greedy, cotengra greedy, and cotengra+KaHyPar on all four benchmark categories. Gray & Kourtis's complementary randomization: parameterize cost(Ti,Tj) = size(Tk) − α(size(Ti)+size(Tj)) with tunable α ∈ [0,1], sample pairs with Boltzmann probability p ∝ exp(−cost/τ) (temperature τ controls "adventurousness"), and repeat many trials while tuning (α, τ) by Bayesian optimization — i.e., turn greedy into a cheap stochastic sampler whose best-of-N tree is the output. Implementation recipe for a TreeSA competitor: run the (α, τ)-Boltzmann greedy with 3-5 fixed cost functions as trial seeds, keep the min-tc tree, spend remaining budget on local search.
- **Applies when**: Very large, sparse networks (up to ~10^4 tensors, model counting) where SA and partitioning blow the time budget or fail outright; tight optimization budgets (≤1 s) where paths-per-second dominates path quality; as fast seed generators for refinement stages.
- **Limits**: Purely myopic — no lookahead, so on graph-structured problems with good separators cotengra's hypergraph partitioner still wins when given unlimited time; which cost function wins is instance-dependent and the mapping is empirical, not principled; Boltzmann sampling needs many trials plus (α, τ) tuning to be competitive, and Hyper-Greedy scales badly in trial count on very edge-dense networks.
- **Sources**: [orgler_2024_optimizing], [gray_2020_hyper]

### Exact methods & optimality bounds
- **Technique**: Three transferable exact/near-exact machines. (1) *Positive-instance-driven (PID) Bouchitté–Todinca DP* (Tamaki): for the decision problem "tw(G) ≤ k", enumerate only *feasible* objects — I-blocks (N(C),C) with C inbound, O-blocks with C outbound, and buildable potential maximal cliques (PMCs) — via binary recurrences: a feasible I-block Cᵢ combines with a stored feasible O-block B (Cᵢ ⊆ B, |N(Cᵢ)∪N(B)| ≤ k+1) to yield new PMCs K = N(Cᵢ)∪N(B) and O-blocks; new O-blocks A spawn PMCs K = N(A)∪(N(v)∩A). Runtime O*(|I|·|O|), sensitive to the count of positive instances (observed orders of magnitude below theoretical |Π| bounds); superset queries use a trie "block sieve" pruned by margin k+1−|N(U)|. (2) *Bracketing exact width from both sides* (Tamaki 2022): upper bound = run BT DP restricted to a heuristically grown PMC set Π (Merge(Π,Ω) adds maximal cliques of a minimal triangulation of N[C]∩N[D] between non-crossing bags), lower bound = grow a minor sequence H₀,H₁,… with tw(Hᵢ) strictly increasing (Lift/BreakFill guided by a "critical fill" e and by counting minimal separators safe-for-width-k crossing e, ncs_k → 0 at lifted elements); terminate when bounds meet, yielding a compact ≤49-vertex minor certificate. (3) *netcon cost-capped breadth-first search* (Pfeifer): build sets S_c of c-tensor subnetworks cheapest-first, rejecting any pairwise contraction whose cumulative cost exceeds µcap; iterate µcap ← max(µ_next, ξ_min·µcap) with old/new flags so only contractions with µ_old < µ ≤ µcap (or involving a new object) are re-examined; provably prune outer products except when all indices of (AB) go to one tensor C with ξc strictly larger than the dangling dims. (4) *Order-then-tree decoupling* (Ibrahim): given a linear order σ of tensors, an optimal tree for that order is exact polynomial DP c(i,j) = min_k max/sum{cost(X_{i,k}, X_{k+1,j}), c(i,k), c(k+1,j)} in O(|E||V|² + d|V|³); the NP-hard part collapses to finding σ, attacked via multilevel Minimum Linear Arrangement (min Σ w(uv)|σ(u)−σ(v)|) — beat Cotengra/Tamaki/FlowCutter by orders of magnitude in total flops at matched 5–10 s budgets on QAOA circuits.
- **Applies when**: netcon-style exact search: ≲20–40 tensors (uniform-χ networks like MERA); PID/BT: sparse graphs up to a few hundred vertices, tw ≲ 25–35, especially strong for proving *lower bounds* (fewer positive instances when k < tw); UB/LB bracketing: instances too hard for direct exact solvers, minutes-to-hours budget; order-then-tree DP: any graph where an MLA-friendly order exists, seconds budget — a strong cheap component for a portfolio, or an exact post-processing refinement of any heuristic order (TreeSA output included).
- **Limits**: PID blows up when the number of feasible O-blocks explodes (dense random graphs: millions of separators at n=50); treewidth decision optimizes only the max clique (leading tc term, unweighted), not total weighted flops; netcon is exponential in n and its outer-product pruning assumes no dim-1 indices; the MLA heuristic is a proxy — no guarantee σ contains the optimal tree, and the O(|V|³) DP limits per-restart size; Tamaki-2022's Lift can stall paying full exact-solver cost when tw(G/F) already equals tw(G).
- **Sources**: [tamaki_2017_positive], [tamaki_2022_heuristic], [pfeifer_2013_faster], [ibrahim_2022_constructing]

### Treewidth ↔ contraction-tree theory
- **Technique**: Markov–Shi's bridge: define contraction complexity cc(G) = min over edge-contraction orderings π of the max degree of any merged vertex; then **cc(G) = tw(G\*)** where G\* is the line graph of G (Prop. 4.2) — edge contraction in G ≡ vertex elimination in G\*, and induced width = treewidth. The proof is constructive both ways: from a width-d tree decomposition of G\*, repeatedly emit a vertex e ∈ B_ℓ \ B_ℓ' from a leaf bag (all of e's remaining neighbors then share that bag), producing a contraction ordering with cc(π) ≤ d in polynomial time. Sandwich for bounded degree: (tw(G)−1)/2 ≤ tw(G\*) ≤ Δ(G)(tw(G)+1)−1, so simulation cost is T^O(1)·exp(O(tw(G_C))); hence log2 tc of the best tree ≈ treewidth of the line graph (times log2 d for bond dim d). Practical recipe (Dumitrescu): feed the line graph to PACE treewidth solvers (freetdi = PID-ACP, meiji-e = PID-BT, both from PACE 2017), convert the returned tree decomposition to a perfect elimination ordering and then a contraction sequence at equal complexity; equivalently a graph has tw ≤ k iff some elimination order leaves every vertex ≤ k higher-numbered neighbors in the fill-in graph — the exact analogue of max tensor rank along a contraction sequence.
- **Applies when**: uniform (or near-uniform) bond dimensions, so tc is dominated by the single largest contraction and minimizing max-rank ≡ minimizing treewidth; bounded-degree networks (circuits, regular graphs) where the sandwich is tight; whenever a mature treewidth solver ecosystem (PACE) can be borrowed wholesale as a contraction-order backend. freetdi dominates at cc ≤ ~9; meiji-e scales better on dense/large line graphs; both crush QuickBB (up to 5 orders of magnitude faster) on QAOA/MERA instances.
- **Limits**: treewidth targets only the leading-order term — ignores edge weights (heterogeneous bond dims) and total-flops/summed cost, so two equal-width trees can differ substantially in tc; line graphs of high-degree vertices inflate size quadratically (freetdi 250× slowdown from 9:1 to 4:1 2D MERA); the tw(G\*) ↔ tw(G) sandwich loosens by Δ(G) (m-ary tree: tw 1, cc m); exact solvers time out beyond cc ≈ 25–30 with 20-minute budgets and give no anytime intermediate answer (unlike QuickBB), so a heuristic fallback is mandatory.
- **Sources**: [markov_2005_simulating], [dumitrescu_2018_benchmarking]

### Benchmark & evaluation practice
- **Technique**: Gray–Kourtis protocol: benchmark on six graph families spanning structure — random k-regular (k=3,4,5, growing |V|, bond dim 2), random planar (|V|∈[20,200]), 2D square lattices, weighted model counting CNFs, QAOA energy circuits, and RQCs (Bristlecone/Sycamore) — always at a *fixed wall-clock or shot budget per optimizer* (e.g. 5 s, 1 h; 4 cores if parallel), reporting mean contraction width W = max_v ec(v) = log2(largest intermediate) and cost C = Σ_v 2^{vc(v)} (log2/log10 flops), with anytime optimizers (Bayesian-tuned Hyper-*, QuickBB, FlowCutter) sampled as curves of best-so-far vs time. Ground results physically: 2^27 complex tensor = 1 GB; consumer GPU ≈ C~10^15/hour. Slicing overhead must be reported as *total sliced cost* C_s = d_sliced × (per-slice cost), never C/d_sliced, since removing s_sliced indices redundantly repeats contractions; choose slices greedily by recomputing W,C with each index removed (with randomized restarts), and — crucially — score C_s *inside* the optimization loop so trees that slice well are selected. Preprocess with the deterministic simplification cycle (antidiagonal-gauge, diagonal-reduce → hyperedges, column-reduce, rank-simplify, split via SVD) before any path search. Liu et al. add the multi-amplitude convention: for k output configurations, optimize the tree for the *aggregate* cost S_k = Σ_l w_{l+1}·S_{l+1:l} over a static reuse tree (shared subtrees below "bright" open-index tensors), used directly as the loss in KaHyPar-based order search (>10× gain); their Sycamore verification budget: 2^22 slices, 3×10^6 amplitudes, 8.5 days on 107,520 CPUs, and quantum-vs-classical comparisons normalized by XEB fidelity f (k exact amplitudes ≡ k/f noisy samples).
- **Applies when**: comparing optimizers claimed to beat TreeSA/greedy — matched wall-clock anytime curves per family are the fair test; slicing/multi-amplitude accounting matters whenever memory caps or many-output workloads are part of the claim; random-regular + planar + lattice + RQC covers the regimes where optimizer rankings *invert* (Hyper-Par wins on regular/RQC, Hyper-Greedy on planar, tree-decomposition solvers on low-width instances).
- **Limits**: rankings are strongly family-dependent, so single-family wins don't generalize; stochastic optimizers need multiple seeds (tc varies ~5% on random graphs); log-scale metrics hide constant factors (real FLOPs = 2× or 8× C for real/complex) and hardware efficiency (Liu's ma-TNC dropped from 1328× ideal to 40× actual speedup before kernel fusion — theoretical tc alone overstates gains); slicing curves are circuit-specific and degrade sharply once W_s targets fall far below the natural W.
- **Sources**: [gray_2020_hyper], [liu_2022_verifying]
