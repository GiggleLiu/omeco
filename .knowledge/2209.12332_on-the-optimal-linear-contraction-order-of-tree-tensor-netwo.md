# On the Optimal Linear Contraction Order of Tree Tensor Networks, and Beyond

**Authors:** Mihail Stoian, Richard M. Milbradt, C. Mendl

**Citation:** SIAM Journal on Scientific Computing, vol. 46, pp. 647-, 2022

**arXiv:** [2209.12332](https://arxiv.org/abs/2209.12332)

**DOI:** [10.1137/23M161286X](https://doi.org/10.1137/23M161286X)

## Abstract

The contraction cost of a tensor network depends on the contraction order. However, the optimal contraction ordering problem is known to be NP-hard. We show that the linear contraction ordering problem for tree tensor networks admits a polynomial-time algorithm, by drawing connections to database join ordering. The result relies on the adjacent sequence interchange property of the contraction cost, which enables a global decision of the contraction order based on local comparisons. Based on that, we specify a modified version of the IKKBZ database join ordering algorithm to find the optimal tree tensor network linear contraction order. Finally, we extend our algorithm as a heuristic to general contraction orders and arbitrary tensor network topologies.

**I.** **INTRODUCTION**


Originally developed for use in theoretical physics [1]
and in parallel in mathematics [2], tensor networks are
nowadays an active interdisciplinary field of research,
which led to fruitful interchanges and insights between
disciplines [3–9]. From their inception, questions of computational complexity and the feasibility of efficient manipulation of tensor networks played a major role.
In this work, we are concerned with an efficient network contraction algorithm, which can be thought of as
a stepwise transformation of a tensor network into a single tensor. A single step consists of contracting two tensors. This step is repeated until only one tensor remains.
Although the final result does not depend on the order
in which the pairwise tensor contractions are performed,
the overall performance is significantly affected. For this
reason, one aims to find an optimal contraction order
before implementing the actual contraction.
However, finding the optimal order for a generic network of _n_ tensors is an NP-hard problem [10]. Therefore,
one must settle for the exponential algorithm for small
instances, e.g., _n ≤_ 20, and hope for good contraction orders via heuristics otherwise, or focus on tensor network
classes for which the problem becomes tractable. In this
paper, we specify a polynomial-time algorithm for finding the optimal _linear_ contraction order of a _tree_ tensor
network.
**Prior Work.** Pfeifer et al. [11] have devised a graphtheoretic dynamic program for finding optimal contraction sequences, which inherently takes exponential time.
More recently, Gray and Kourtis [12] have introduced a
novel optimizer based on hypergraph partitioning that
has been shown to yield high-quality contraction orders.
Another line of research has focused on parallel contraction algorithms for tensor networks representing quantum circuits, introducing two ad-hoc methods that refine

**A.** **Precedence Graph**


The main idea of the original algorithm comes from the
observation that we are working only with linear orders.
In a linear order, we start with a tensor and then sequentially contract it with neighboring tensors (cf. Sec. II B).
Moreover, since we are working with tree-shaped networks, this naturally imposes a _precedence_ relation on
the tensors of the network. Therefore, we can consider
each tensor as the first element of the solution and thus
root the tree in it. The subsequent tensors to be contracted must obey the precedence relation, i.e., a child
node must not appear in the contraction order before its

**C.** `TensorIKKBZ`


We adapt the `IKKBZ` algorithm to tensor networks,
which we refer to as `TensorIKKBZ` . Intuitively, the algorithm maintains the invariant that the tensors are sorted
based on the score function, _σ_ . [7] However, the precedence
constraints must also be observed. This can lead to a
_contradictory_ sequence that violates the invariant: the
precedence graph requires _A →_ _B_, but _σ_ ( _A_ ) _≥_ _σ_ ( _B_ ). To
restore the invariant, the algorithm merges _A_ and _B_ into
a single node. This node is called a _compound tensor_ and
comprises all the tensors in _A_ and _B_ (which may themselves be compound tensors) in that order. This step is
called _normalization_ .
To see why normalization does not preclude optimality,
consider the following theorem (see [25, Thm. 2]):


**Theorem 2.** _Let {A, B} be a compound tensor._ _If_
_A →_ _B and σ_ ( _A_ ) _≥_ _σ_ ( _B_ ) _, then there exists an optimal_
_sequence in which B directly follows A._


Appendix A 2 contains a proof of this theorem.

_2._ _Time Complexity_


The first phase, constructing the precedence graph, can
be done by depth-first search in linear time [28], starting
from the root and routing the edges to the unexplored
nodes of the tree. In the second phase, linearization is
the most expensive operation: Interleaving _m_ linearizations of total size _n −_ 1 runs in _O_ ( _n_ log _m_ )-time via a
min-heap data structure of size _m_ [17]. In contrast, the
normalization operation takes linear time. Since the algorithm repeats the two phases for each of the _n_ tensors,
its total time complexity is _O_ ( _n_ [2] log _n_ ) [26].
Krishnamurthy et al. [27] improved the original `IKKBZ`
algorithm to run in _O_ ( _n_ [2] )-time by observing that the
linearizations of two adjacent nodes are similar. We
can apply the same observation in our context so that
`TensorIKKBZ` runs in _O_ ( _n_ [2] )-time as well.

**A.** **Linearized Dynamic Programming**


Textbooks introduce dynamic programming with the
classical problem of matrix-chain multiplication and its
cubic-time solution [17]. Matrices are a special class of
tensors. Consequently, this problem is in fact the optimization problem on _chain_ tensor networks. To apply
the same algorithm, we need to find a way to transform



the tensor network into a chain, i.e., to find an order
(permutation) of its tensors. We can then apply the
cubic-time dynamic program to optimize the parenthesization of the tensors, which corresponds to the optimal
contraction tree respecting the fixed permutation.
This idea was explored by Neumann and Radke [18] in
the context of join ordering. The novelty in their work
consists in using the linearizations of the `IKKBZ` algorithm
as seeds for the permutation, which guarantees optimality in the regime of linear orders. The technique is called
linearized dynamic programming, `LinDP` for short, and
has been shown to yield near-optimal _general_ join orders.
We show that `LinDP` can be used with `TensorIKKBZ` to
provide near-optimal _general_ contraction orders for tree
tensor networks.
**Pseudocode.** We outline the pseudocode in Alg. 3
(see Appendix B for an extended version). In principle,
one can apply the dynamic programming step only to
the optimal linear order provided by `TensorIKKBZ` . Note,
however, that `TensorIKKBZ` considers _each_ tensor as the
root of the precedence graph anyway. As a consequence,
we obtain _n_ many such linearizations, all of which can be
used as initial permutations (line 5). This gives the algorithm more flexibility to find better general contraction
orders.
**Time Complexity.** The fact that `LinDP` considers
all `TensorIKKBZ` linearizations makes it an expensive algorithm. Namely, its time complexity is _O_ ( _n_ [4] ), since
it runs the cubic-time dynamic program for each tensor
separately (line 6). This problem can be alleviated by
parallelizing the main for-loop (line 4).

**B.** **Join Ordering**


The result of a query consists of a single table that represents the join of all tables present in the query. However, joining the tables in the order specified by the user,
e.g., by means of an SQL query [29], can lead to slow

or approximate the optimal execution order of the joins.

corresponds to the outer tensor product, i.e., there is no

_2._ _New Aspects of Contraction Ordering_


There are several differences which, at first sight, impede results in join ordering, notably optimality results,
to be applicable to tensor networks:
1) _Tensor Contraction Cost._ The sizes of the to-becontracted legs between two tensors do not appear in the
later contraction costs in which the contracted tensor is
involved. In contrast, in join ordering, the weights of
the join edges, which represent join selectivities, are still
multiplied by in later join costs. An example is provided
in Appendix C.
2) _Open Legs._ Another particularity of tensor networks is the presence of open legs. Graphically, they
are edges with only one endpoint and persist in the tensor network during its contraction. There is no explicit
definition of them in the setting of join ordering we are
considering, and thus the algorithms are not designed to
support them.

**VI.** **BENCHMARKING AND EVALUATION**


To demonstrate the advantage of having an optimal algorithm as a starting point for further heuristics,
we compare both `TensorIKKBZ` and `LinDP` against the

recently proposed hyperoptimizer by Gray and Kourtis [12], `ctg.Hyper-Par`, which uses as subroutine the
`KaHyPar` hypergraph partitioner [31]. It has been shown
to achieve competitive contraction costs on the tensor networks of several quantum circuits, including the
Google Sycamore quantum circuit [32].
**Setting.** We benchmark against two classes of tree
tensor networks, the Hierarchical Tucker (HT) and the recently proposed Fork-Tensor Product State (FTPS) [33].
Their graphical notations are both illustrated in Appendix E 1. The leg sizes are randomly chosen between
1 and 256. We also benchmark on the Sycamore circuit
for which we need the spanning tree heuristic described
in Sec. IV B (experiment results in Appendix E 2).
In Fig. 9, we plot the contraction cost, _C_, and the optimization time for their _closed_ counterparts, i.e., without open legs. In the experiments, we let the algorithms
fully exploit the potential of parallelization (in our case,
20 physical cores). Moreover, to ensure fairness, we let
`ctg.Hyper-Par` sample contraction orders _n_ times (the
default value is 128), since both `TensorIKKBZ` and `LinDP`
generate _n_ orders as well. Both of our optimizers are
implemented in `C++` and wrapped to be used directly in
`opt_einsum` [34] and `cotengra` [12]. Our implementation
is publicly available. [8]

**Contraction Cost.** The first observation is that, for
FTPS, while linear contraction orders are more restrictive than general contraction orders, `TensorIKKBZ` is on
par with `ctg.Hyper-Par`, which outputs general contraction orders. This is because `TensorIKKBZ` returns the optimal linear contraction order, thus providing robustness.
In addition, `LinDP` consistently outperforms
`ctg.Hyper-Par` by almost an order of magnitude
in both classes since it builds the optimal contraction
tree respecting `TensorIKKBZ` ’s linearization. For small
instances, it is on par with the exact exponential dynamic
programming of `opt_einsum`, `oe.DynamicProgramming` .
**Optimization Time.** Both of our optimizers are
faster than `ctg.Hyper-Par` . This is partly due to the
performance of `C++`, but also to the good time complexity of the algorithms and their parallelization potential.


**VII.** **CONCLUSION**


We proved that tree tensor networks admit optimal
linear contraction orders in polynomial time. To this
end, we provided the `TensorIKKBZ` algorithm, which is
an adaptation of a decades-old algorithm from database
join ordering. It requires the cost function to satisfy the
adjacent sequence interchange (ASI) property. Thus, we
proved that the cost function used in the context of tensor
networks does indeed satisfy this property.

**Appendix B:** `LinDP` **: Extended Pseudocode**


In Sec. IV A we only provided a shortened version of the pseudocode, as the underlying dynamic program is exactly
the solution to the well-known matrix-chain multiplication problem [17]. In Alg. 4, its extended version is outlined.
The algorithm aims to find the optimal contraction tree respecting an initial linear order (sequence) _S_ of the tensors.
To this end, it exploits Bellman’s optimality condition [38], which states that if a problem _P_ has an optimal solution
_S_ _[∗]_ := _S_ 1 _S_ 2, then both _S_ 1 and _S_ 2 are optimal solutions for _P_ 1 and _P_ 2, respectively, with _P_ = _P_ 1 _P_ 2. In our context,
this means that every contraction subtree of the original contraction tree must be an optimal contraction tree for the
tensors it contains.
Once the precedence graph _T_ [ _i_ ] of _T_ [[] _[i]_ []] has been linearized, the key idea is to compute ( ) for all intervals
_P_ _C_ _·_

[ _i, j_ ] _, i ≤_ _j_, using Eq. (3). These values are stored in the dynamic programming table `dp` of size _n × n_ . For the
base case in Eq. (3), we initialize `dp` [ _i, i_ ] to 0, _∀i ∈_ [ _n_ ] (line 6). Subsequently, we fix an interval size _s_ and iterate all
intervals of that size. Then, by employing Bellman’s optimality principle, we have to guess where the problem [ _i, j_ ]
splits. This is represented by the index _k_, for each of which we compute the cost (cf. Eq. (3)) and compare with
the current minimum obtained for [ _i, j_ ] (lines 11-12). If the current _k_ improves the cost, we store it in the table `opt`
(of size _n × n_ ) which will be used to reconstruct the contraction tree of optimal cost. Finally, after the cubic-time
algorithm has finished, we update the contraction tree _τ_ in case the cost `dp` [1 _, n_ ], the optimal contraction cost for the
given linearization, is better. If so, we reconstruct the contraction tree using the table `opt` (line 20).

An execution of the algorithm is visualized in Fig. 12. We are considering only the precedence graph of _T_ [[4]], but the
algorithm would have to consider all precedence graphs. In the first phase, the algorithm builds the precedence graph

the algorithm merges the linearizations of _T_ [[1]] and _T_ [[5]], which in this case are the nodes themselves, by observing the
score monotonicity w.r.t. “ _≤_ ” (as defined in Thm. 1). After the merge step, a normalization step is required (step 3 ),
since _T_ [[2]] _→_ _T_ [[1]], but _σ_ ( _T_ [[1]] ) _≤_ _σ_ ( _T_ [[2]] ). This creates the compound tensor _T_ [[2]] _T_ [[1]] which comprises both _T_ [[2]] and
_T_ [[1]], in that order. Its score is calculated as described in Alg. 2.
Afterward, we are able to linearize _T_ [[4]] and, in the final step, denormalize it, i.e., resolve the compound tensors
into their constituent tensors. In our case, the compound tensor _T_ [[2]] _T_ [[1]] is decomposed into individual tensors, as in
step 5 . Finally, we obtain the optimal linear contraction order for the precedence graph of _T_ [[4]] . That is, _T_ [[4]] should
be contracted first with _T_ [[3]], then with _T_ [[2]], followed by _T_ [[1]] and _T_ [[5]] .

**2.** **Sycamore**


The Sycamore architecture is the one used and executed in the quantum supremacy experiment of Arute et al. [32].
In our experiments, we enable local optimization [14] and suffix the optimizers where we have enabled it with “+”. For
`ctg.Hyper-Par`, we use the default value for the number of samples, 128. Note that in this setting, the underlying
tensor network is not tree-shaped. Hence, as discussed in Sec. IV B, we need to choose a spanning tree of the tensor
network. In Fig. 14, we plot both the contraction costs and the optimization times.
First, since the underlying tensor network of the Sycamore circuit is a generic one, our algorithms cannot provide
any optimality guarantee (but rather only on the minimum spanning tree provided). Second, we observe that for
a small number of cycles, namely less than or equal to 14, `LinDP` is on par with `ctg.Hyper-Par` . However, as the
number of cycles increases, the contraction costs offered by `LinDP` become less competitive. Moreover, `LinDP` suffers
from its quartic time complexity. Since our main technical result is the `TensorIKKBZ` algorithm, we leave it as future
work to further improve both the contraction costs and optimization times of `LinDP` in the context of tensor networks.
